skaegis

Your continuous shield. Every CVE seen, every gap closed.

skaegis watches every machine you run, Linux servers, Windows laptops and Macs. The moment a new CVE is published against something you have installed, it tells you, ranks it by how exploitable and how exposed it is, and hands the fix to your patch pipeline. On your own infrastructure.

What skaegis is

Continuous vulnerability intelligence for your whole fleet, from one self-hosted service. Detection through to remediation as a closed loop, with no SaaS in the middle and no inventory leaving your network. skaegis is the Detect pillar of the SKWorld security suite.

Linux · Windows · macOS CVE detection closed-loop self-hosted no SaaS

Status: in design and early build. Tiers and scope below describe the plan, not a shipped release.

§Why now

New CVEs land on already-deployed hosts every day. The software on your laptops and servers did not change, but what is known about it did. A quarterly scan is stale the week after it runs, and a scanner that only covers the Linux rack leaves every laptop as a blind spot.

So detection has to be continuous, and it has to be cross-OS: new advisories matched against what is actually installed on each host as they land, on every platform you run, with the short list ranked so the top of it is the one worth your morning.

What skaegis does not claim: it does not find unknown flaws, a host without an agent is not covered, and it reduces exposure rather than making a system impossible to breach.

§How it works: the loop

A finding is not done when it is reported. It is done when a re-scan shows it gone.

1. Detect agents inventory installed software on every host public CVE feeds (NVD, GHSA, OSV, vendor) matched continuously -> finding: CVE, host, package, severity, fix-available 2. Triage rank by exploitability x exposure, using a model run locally -> critical and reachable: same-day lane, the rest: batched 3. Remediate package updates for hosts, pull requests for dependencies and images -> handed to your patch pipeline, a human or the change gate approves 4. Verify next inventory scan: is the CVE gone and are services healthy? no -> back to Detect 5. Confirm CVE absent -> the change is closed
  1. Detect. Agents report installed software on every host. New CVE data is matched against it continuously, with severity and whether a fix exists.
  2. Triage. Findings are ranked by exploitability and exposure. The model doing the ranking runs locally, so context stays in-house.
  3. Remediate. The fix goes into your patch pipeline. skaegis drafts, it never auto-merges.
  4. Verify. skaegis re-scans. When the CVE no longer appears, the finding closes. If it does, it stays open.
  5. Confirm. The change is closed on evidence. A finding with no fix yet stays open and marked, never silently dropped.

Honest limit: there is a lag between a patch landing and a clean re-scan, and Windows and macOS auto-apply is a later phase.

§What it detects

Per-host CVEs

Installed packages matched against public vulnerability sources, on Linux, Windows and macOS, host by host.

Fix available, with severity

Every finding carries severity and whether a fixed version exists, so triage starts with what can actually be closed today.

CIS and SCA posture

Configuration checks against hardening benchmarks, to catch misconfiguration as well as vulnerable software.

File integrity monitoring

Watch the paths that matter and see when they change.

One dashboard

The fleet's open findings in one place, behind your own single sign-on.

Pipeline hand-off

Findings flow into your existing patch, ticketing and notification tools instead of a separate inbox.

Under the hood the detection engine is unmodified upstream Wazuh, run from pinned images and packaged with SSO, ingress and backups as one product.

§Tiers

Straight answers

Does data leave my network?

No. Host inventory, findings and triage stay on your infrastructure. It pulls public vulnerability feeds in and sends nothing of yours out.

Does it find everything?

No tool does. It detects known, published CVEs on software it can see on enrolled hosts. Unknown flaws and hosts without an agent are out of scope.

Does it fix things on its own?

Only at Guard and above, and through your own patch pipeline, so your review and change process still applies.

Can I use it today?

Not yet. It is in design and early build. Watch the repository for updates.
